Коротко: для новичков в веб-скраппинге достаточно уверенно освоить селекторы по тегу, классу, ID, атрибуту, а также базовые комбинаторы (пробел, >, +, ~) и несколько псевдоклассов (nth-child, first/last-child, not). Ниже — понятные примеры и практические советы под парсинг.

## Базовые селекторы

- По тегу: выбирает все элементы определенного типа.
  - Примеры: div, a, img, table, tr, td
  - В скраппинге: soup.select("a") — все ссылки; soup.select("tr") — все строки таблицы.

- По классу: точка + имя класса.
  - Примеры: .item, .product-card, .title
  - В скраппинге: soup.select(".product-card .title")

- По ID: решетка + id (уникален на странице).
  - Примеры: #header, #main, #login-form
  - В скраппинге: soup.select("#login-form input")

- Универсальный селектор: звездочка.
  - Пример: * выбирает все элементы; полезно редко, чаще — в сочетании с комбинаторами.

## Комбинаторы (связи между элементами)

- Потомок: пробел между селекторами.
  - div a — любые ссылки внутри div (на любой глубине)
  - .card .price — элемент с классом price где-то внутри .card

- Прямой ребенок: >
  - div > a — только ссылки, чьи родители — непосредственные div
  - ul > li — элементы списка только первого уровня

- Сосед справа (непосредственно следующий): +
  - h2 + p — параграф, который идет сразу после h2

- Все последующие соседи: ~
  - h2 ~ p — все параграфы после h2 на том же уровне вложенности

## Селекторы атрибутов

- По наличию атрибута:
  - [href], [data-id], [aria-label]

- По точному значению:
  - a[target="_blank"], input[type="email"]

- По началу значения:
  - a[href^="https://"], img[src^="/images/"]

- По окончанию значения:
  - a[href$=".pdf"], img[src$=".jpg"]

- По вхождению подстроки:
  - a[href*="product"], div[class*="col-"]

- По слову в списке классов (чаще уже решает .class):
  - [class~="active"]

Примечание: для динамично генерируемых страниц часто удобнее цепляться к устойчивым data-атрибутам (data-id, data-testid, role, aria-*).

## Группировка и комбинирование

- Группировка через запятую:
  - h1, h2, h3 — выбрать сразу несколько типов
  - .price, .cost, .amount — собрать однотипные поля

- Сочетание условий:
  - a.btn.primary[href^="/buy"] — ссылка с двумя классами и с нужным href

## Частые паттерны под скраппинг

- Карточки списка:
  - .card .title, .card .price, .card a[href] — собрать название, цену, ссылку

- Таблицы:
  - table.data > thead th — заголовки
  - table.data > tbody tr — строки
  - table.data > tbody tr > td:nth-child(3) — третий столбец

- Навигация/пагинация:
  - nav.pagination a[rel="next"] — кнопка «Далее»
  - ul.pagination li.active + li a — ссылка на следующую страницу

- Хлебные крошки и метаданные:
  - nav.breadcrumbs a — пути разделов
  - meta[name="description"] — описание страницы
  - link[rel="next"], link[rel="prev"] — ссылки на соседние страницы

## Псевдоклассы для выборки

- :first-child / :last-child
  - ul.items > li:first-child — первый элемент списка
  - .row > div:last-child — последний столбец в строке

- :nth-child(n) / :nth-of-type(n)
  - .table tr:nth-child(2) — вторая строка (включая заголовок, если он в tbody)
  - .table td:nth-of-type(3) — третий столбец по типу td

- :not(...)
  - .product:not(.out-of-stock) — все товары, кроме помеченных как «нет в наличии»

- :has(...) — почти нигде не поддерживается в парсерах, не рассчитывать на него.

Совет: при парсинге лучше опираться на nth-child для стабильных колонок, а не на визуальный порядок, который может меняться.

## Советы по стабильности селекторов

- Отдавать приоритет устойчивым атрибутам:
  - data-id, data-qa, data-testid, role, aria-label
  - Пример: [data-testid="product-title"]

- Избегать хрупких конструкций:
  - Глубокие цепочки вида .container > div > div > div .title ломаются при малейшей правке верстки.
  - Лучше короче и точнее: .product-card .title или [data-id] .title

- Уточнять контекст:
  - article.post .title — заголовки внутри постов, а не в сайдбаре
  - main .price — цены только из основной области, не из рекламы

- Комбинировать несколько признаков:
  - a.btn.primary[href*="checkout"] — конкретизирует «правильную» кнопку

## Мини-«шпаргалка» для парсера

- Все карточки: .card
- Заголовок карточки: .card .title
- Цена: .card .price, .card [data-price], .card [itemprop="price"]
- Ссылка на карточку: .card a[href]
- Табличные данные: table.data > tbody > tr > td
- Пагинация «далее»: nav.pagination a[rel="next"], a[aria-label="Next"], a[href*="page="]
- Изображение: img[src], .card img[src^="http"]

## Практические примеры с пояснениями

- Все ссылки на продукты:
  - a[href*="/product/"] — ищет подстроку в href
- Записи блога с датой:
  - article.post time[datetime] — элементы time с атрибутом datetime
- Кнопка «Купить» только на карточке:
  - .card a.btn.buy[href^="/buy"] — в карточке, кнопка с href начинающимся на /buy
- Заголовки H2 внутри контента:
  - .content h2 — все H2 в блоке .content
- Исключить рекламные блоки:
  - .item:not(.ad) — элементы .item, которые не имеют класса ad

## Частые ошибки

- Слишком общий селектор: .title может встречаться в разных местах; уточняйте контекст: .product .title.
- Привязка к позициям, которые «плавают»: .grid > div:nth-child(3) — может сломаться при изменении сетки; лучше использовать класс или data-*.
- Использование автогенерируемых классов (например, .css-1a2b3c) — они часто меняются; ищите семантические классы или атрибуты.
